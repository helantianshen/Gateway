- 范围：Host 索引、非法 Host、405/Allow、路径语义、独立差分测试、性能矩阵和有证据的参数分配优化
- 顺序：1 基线 → 2 Host 索引 → 3 Host 错误 → 4 Method 错误 → 5 Path 语义 → 6 profile → 7 根据数据决定优化
- 基线：Linux amd64；Go 1.27.1-X:nodwarf5，项目/CI 为 1.26.5；用户已修改 configs/gateway.yaml，保留原样
- 约束：现有冻结 Radix 保留；不引入 unsafe、Pool、外部 Router；不提交或推送
- 状态：Step 1–7 完成；最终文档、fuzz 与复核完成。性能原始结果存放 benchmarks/results/router/2026-09-29/
- 已验证：阶段 Router/Gateway/config 单测与 race、全仓库 test/race/vet；现有不可变结构与 reference 保留
- 性能：10k Host exact 基线约 36.6µs，索引阶段约 390ns；参数优化单独使三参数 560B/8 alloc 降为 464B/5 alloc，另消除小写 DNS Host 的两处分配
- API：NormalizeHost 返回 (string, *MatchError)；MatchError 增加 IllegalHost/MethodNotAllowed/AllowedMethods；Router.AllowedMethods 返回有限列表、any 标记与错误
- Path：decoded template，%/?/# 字面可达；Unicode 保留；控制字符、反斜杠、dot、非法 UTF-8 拒绝；请求斜杠不清理
- 未改变：Params map API、控制面规划、此前 R1–R5 缺陷及用户 configs 修改
- 语义：Host 优先级保留逐层回退；405 在全部成功路径失败后汇总匹配 Host 的允许方法；OPTIONS 不自动响应

- 最终验证：make verify（diff/gofmt/vet/test/race/build）通过；四个 fuzz 各 10 秒通过，最后的 Method miss 跳过逻辑再次经过请求差分 fuzz 10 秒；真实 HTTP 与文档链接检查通过
